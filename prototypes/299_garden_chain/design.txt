# 299 — GARDEN CHAIN Design Spec

## Concept
A grid-garden where plants grow, spread, and overgrow. The player is a gardener
who clicks to harvest same-colored plant clusters, chaining COMBOs for score.
The garden is alive: seeds sprout from nowhere (CA "growth/infection" hook) and
existing plants spread to adjacent empty soil, so the board constantly refills
and threatens to overgrow. Harvesting is the only way to keep the garden under
control — but the color of each consecutive harvest matters. This is the first
gardening / plant-breeding genre in the prototype collection.

Reinterpreted from auto-shooter/space-mining idea #1 (Score 31.45):
  "CA grid fills up (infection/growth) to control" -> plants sprout + spread via CA
  "synthesis compression" -> same-color COMBO chain -> SUPER HARVEST (rainbow)

## "Most Fun Moment" (面白い瞬間)
増え続ける庭で、同色の大きな塊（クラスタ）を見極めて一気に収穫し、COMBO連鎖と
SUPER HARVESTの虹色モードで次々と刈り取っていく快感。

## Core Mechanic
1. A 10x8 grid of soil cells. Some cells hold a plant of one of 4 colors.
2. Every GROW interval, each plant has a chance to spread to one adjacent empty
   cell (same color). Every SPROUT interval, a new random-colored seed sprouts in
   a random empty cell. The board steadily fills up.
3. Player clicks a plant cell -> the ENTIRE same-color orthogonally-connected
   cluster (BFS) is harvested in one click, scoring points per plant.
4. Consecutive harvests of the SAME color build COMBO (multiplier). Harvesting a
   different color = mismatch (COMBO resets, HEAT +15). Clicking empty soil = miss
   (HEAT +5, combo reset).
5. COMBO >= 4 triggers SUPER HARVEST (300 frames): any color counts as a match,
   score x3, rainbow border. Lets the player sweep clusters freely.
6. Risk: if the garden overgrows (occupancy >= threshold), HEAT rises every frame.
   HEAT reaches 100 -> game over. 60-second timer -> game over (final score).
7. Decision loop: harvest a cluster now (safe, keeps board clear) vs wait for it
   to grow bigger (more points per click) — but waiting lets the board overgrow
   and risks breaking your combo when the color runs out.

## Technical Spec
- Screen: 320x240, display_scale=2, Pyxel 2.x
- Grid: 10 cols x 8 rows, CELL=24 px. Playfield 240x192 at offset (40, 24).
- Phase machine: TITLE, PLAYING, GAME_OVER (3 phases)
- Colors: plants RED=8, LIME=11, DARK_BLUE=5, YELLOW=10; soil BROWN=4;
  HUD white=7; heat bar gradient RED=8/ORANGE=9/YELLOW=10/LIME=11.
- EMPTY cell value = -1 (int grid: list[list[int]]).

## Key Methods (Testable — NO pyxel input/btn calls inside)
- `_bfs_cluster(self, col, row, color) -> set[tuple[int, int]]` — orthogonal
  same-color connected cells starting at (col,row). Returns set of (col,row) tuples.
- `_harvest(self, col, row) -> int` — harvest cluster at (col,row). Returns points
  gained (0 if empty cell). Handles match/mismatch/miss, combo, super activation,
  cluster clearing, particle/text spawning. Does NOT read pyxel input.
- `_grow(self) -> None` — one CA spread tick: for each plant, with probability
  SPREAD_CHANCE=0.5 spread to a random adjacent empty cell (same color).
- `_sprout(self) -> None` — spawn one plant of random color in a random empty cell.
- `_update_heat(self) -> None` — game-over check FIRST (heat >= 100 -> GAME_OVER),
  then decay heat = max(0, heat - HEAT_DECAY).
- `_update_overgrow(self) -> None` — if occupancy >= threshold, heat += OVERGROW_HEAT.
- `_update_timers(self) -> None` — decrement time_left, increment elapsed, tick
  grow/sprout counters (call _grow/_sprout when they hit 0 and reset), decrement
  super_timer (deactivate at 0), update particles/texts, check timer<=0 -> GAME_OVER.
- `_grow_interval(self) -> int` — 45 -> 20 linear over GAME_DURATION.
- `_sprout_interval(self) -> int` — 60 -> 35 linear over GAME_DURATION.
- `_overgrow_threshold(self) -> float` — 0.8 -> 0.6 linear over GAME_DURATION.
- `_occupancy(self) -> float` — plant_count / (COLS*ROWS).
- `_plant_count(self) -> int`.
- `_activate_super(self) -> None`.
- `_cell_from_xy(self, x, y) -> tuple[int,int] | None` — mouse px -> (col,row) or None.
- `reset(self) -> None` — init all state, seed INITIAL_PLANTS random plants.

## Phase Machine
TITLE --(SPACE/RETURN/click)--> PLAYING --(auto: heat>=100 or time<=0)--> GAME_OVER --(SPACE/RETURN)--> PLAYING (fast restart)

## Screens
1. TITLE: "GARDEN CHAIN" title, 4-color plant legend, "CLICK TO HARVEST / SPACE START"
2. PLAYING: soil grid + plants (circles), HUD (score, combo, timer bar, heat bar)
3. GAME_OVER: reason ("OVERGROWN!" or "TIME UP!"), final score, best score, restart prompt

## Rendering Notes
- Empty soil cell: BROWN(4) filled square inset by 3px.
- Plant: filled circle (pyxel.circ) radius 7 at cell center in plant color, plus a
  small lime leaf dot.
- HUD: score top-left (white), "COMBO xN" top-center (yellow, rainbow during super),
  TIMER bar top horizontal (white->red as time runs low), HEAT bar vertical right
  (green->yellow->red by value).
- SUPER mode: rainbow border around playfield, plants pulse.
- Screen shake: self._shake frames, applied via pyxel.camera offset (guard with
  try/except in headless tests).

## Animation / Timing Rules
- 60fps. game duration 3600 frames.
- SUPER duration 300 frames, then super_active=False.
- Particle lifecycle: life decremented each frame; removed when <= 0. Spawn life>=2
  so tests can observe one update.

## Particle System
- Harvest: 8 particles, color = plant color, vx/vy random [-1.5,1.5], life 15-25.
- Super activate: 20 particles, rainbow colors, life 20-30.
- Mismatch: 4 particles, RED, life 10.
- Miss: 4 particles, GRAY, life 10.
- No gravity.

## Floating Text
- "+{gain}" at cluster center (white/plant color).
- "COMBO x{n}" (yellow).
- "SUPER HARVEST!" (rainbow/yellow).
- "WRONG!" (red) on mismatch, "EMPTY!" (gray) on miss.
- life starts >= 20, decremented, removed <= 0.

## Input
- MOUSE_BUTTON_LEFT in PLAYING -> _cell_from_xy(mouse_x, mouse_y) -> _harvest.
- TITLE: SPACE or KEY_RETURN or click -> reset() + phase=PLAYING.
- GAME_OVER: SPACE or KEY_RETURN -> reset() + phase=PLAYING.
- ESC key -> pyxel.quit().

## Headless Testing Pattern
- Use `Game.__new__(Game)` to bypass __init__ (avoids pyxel.init/run panic).
- Pre-init ALL instance attributes before calling reset() (see Game.__new__ pitfall).
- Never call pyxel.btn/btnp/mouse_x/mouse_y in testable methods.
- `_harvest`, `_grow`, `_sprout`, `_update_heat`, `_update_overgrow`, `_bfs_cluster`
  are the primary test targets. Call them directly with state manipulation.
- Provide `_make_game()` factory in test file: Game.__new__ + pre-init + reset()
  + seed g._rng = random.Random(42).

## Edge Cases
- Empty grid (all EMPTY) -> _harvest on any cell = miss.
- All same color -> cluster BFS returns whole connected region.
- Full grid (no empty cells) -> _grow/_sprout are no-ops.
- First harvest ever (last_color None) -> always matches, no penalty.
- Mismatch when super_active is True -> still matches (no penalty).
- Heat exactly 100 -> game over BEFORE decay (threshold check first).
- Timer exactly 0 -> game over.
