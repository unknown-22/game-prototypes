# 308 — TEA CHAIN (茶道 Tea Ceremony) Design Spec

## Concept
You are a tea master (茶人) running a small tea house. A stream of guests arrives, each with a
requested tea type (their "order" shown as a colored thought bubble). You brew tea — your current
brew color auto-cycles among 4 tea types. A "steep meter" fills continuously while you brew: the
longer the tea steeps before you serve, the more points it's worth (up to 3x), but if you let it
steep too long it over-steeps and becomes BITTER (HEAT penalty). Serve by clicking a guest (or
pressing 1/2/3) when your brew color matches their order. Same-color consecutive correct serves
build a COMBO chain; at COMBO>=4 you enter SUPER BREW (rainbow, any color matches, 3x score, HEAT
frozen). HEAT fills on mistakes and ends the game at 100. Survive 60 seconds and chase a high score.

## "Most Fun Moment" (面白い瞬間)
注文の色を読んで、点てた茶が濃くなるのをギリギリまで待って（steepメーターで倍率アップ）、
同色を連続で供して虹色のSUPER BREWでコンボが伸びる瞬間。

## Core Mechanic (game loop)
1. A guest spawns into an empty seat with a random requested color (0-3), shown as a colored bubble.
2. Your brew color auto-cycles through 4 tea types every CYCLE_F frames (20f -> 12f over 60s).
3. Steep meter fills +1 per frame, capped at STEEP_MAX=45. When it reaches STEEP_MAX without a
   serve, the tea OVER-STEEPS (bitter): HEAT+12, steep resets to 0 (combo NOT reset).
4. Player decides: serve now (safe, 1x) or wait for steep (up to 3x) — but risk over-steep and risk
   the brew color cycling away from the guest's order before you can serve.
5. Serve (click guest / press 1,2,3):
   - MATCH (brew_color == guest.requested_color, or SUPER active = any color):
     steep_mult = 1 + steep // 15  (steep 0-14 -> 1x, 15-29 -> 2x, 30-44 -> 3x)
     combo += 1; max_combo tracked; mult = steep_mult * (3 if SUPER else 1)
     score += 10 * combo * mult; steep = 0; guest leaves (happy particles)
     if combo >= 4: activate SUPER BREW (super_timer = 300)
   - WRONG (mismatch, no SUPER): HEAT += 15, combo = 0, steep = 0, guest stays, floating text "WRONG!"
6. COMBO >= 4 -> SUPER BREW: 300 frames of rainbow border, any color matches, 3x score, HEAT frozen
   (no decay, mismatches impossible because all colors match).
7. Guest patience: PATIENCE_MAX=600 frames; when it hits 0 the guest walks out (HEAT+5, combo=0).
8. HEAT: mismatch +15, over-steep +12, guest-left +5, decay -0.02/f (frozen in SUPER), cap 100 ->
   GAME OVER (check heat>=100 IMMEDIATELY after any increment AND in _update_heat BEFORE decay).
9. Timer: 60 seconds (3600 frames at 60fps) -> game over.

## Technical Spec
- Screen: 320x240, display_scale=2, Pyxel 2.x, fps=60
- Phase machine: TITLE, PLAYING, GAME_OVER
- 3 guest seats at x = [70, 160, 250], y = 70; seat hitbox 48x48 centered on each seat point
- Tea master station at right (x ~ 280)
- Colors (tea types), raw ints:
  0 = RED(8)       = "HIBISCUS"
  1 = LIME(11)     = "MATCHA"
  2 = DARK_BLUE(5) = "OOLONG"
  3 = YELLOW(10)   = "CHAMOMILE"
  Brew color cycles in order 0 -> 1 -> 2 -> 3 -> 0 ...

## Key Methods (Testable — NO pyxel input calls)
- `serve(seat: int) -> str` — serve guest at seat; returns "match" / "wrong" / "empty". Handles
  combo, score (with steep mult and SUPER 3x), heat on mismatch, super activation. Call
  `_check_game_over()` after any heat increase.
- `_update_steep() -> None` — steep += 1; if steep >= STEEP_MAX: heat += 12; steep = 0.
- `_update_brew_color() -> None` — color_timer -= 1; at 0 advance brew_color = (brew_color+1)%4,
  reset color_timer to current cycle length.
- `_spawn_guest() -> None` — if an empty seat exists, place a Guest(seat, rng.randrange(4),
  PATIENCE_MAX).
- `_update_guests() -> None` — decrement each patience; remove expired guests (heat += 5, combo = 0).
- `_update_heat() -> None` — if heat >= MAX_HEAT: phase = GAME_OVER; return. else heat =
  max(0.0, heat - DECAY) (skip decay when SUPER active).
- `_update_particles() -> None` — move, decrement life, remove dead (life <= 0).
- `_update_floating_texts() -> None` — move up, decrement life, remove dead.
- `_check_game_over() -> None` — if heat >= MAX_HEAT or timer <= 0: phase = GAME_OVER,
  best_score = max(best_score, score).

## Phase Machine
```
[TITLE] -> (KEY_RETURN / SPACE) -> [PLAYING] -> (heat>=100 or timer<=0) -> [GAME_OVER] -> (KEY_RETURN / SPACE) -> [TITLE]
```

## Screens
1. TITLE: "TEA CHAIN" title, subtitle "Tea Ceremony Chain", controls text (Click / 1-3 to serve,
   steep for 3x, don't over-steep), "Press ENTER".
2. GAME: 3 guest seats with colored thought bubbles (request color), tea master + current brew
   color swatch, steep meter bar, HUD (SCORE / COMBO / HEAT bar / TIMER bar). Rainbow border in
   SUPER. Guests have a patience bar under their bubble.
3. GAME_OVER: "GAME OVER", final score, best score, max combo, "Press ENTER".

## Rendering Notes
- Background NAVY(1) or BLACK(0); tea house tatami floor as BROWN(4) band at bottom.
- Guest: WHITE(7) circle head + body, thought bubble = small circle + text of tea name, colored by
  requested color. Patience bar (GREEN->RED) under each guest.
- Brew color swatch near master: filled circle/rect in current brew color, label with tea name.
- Steep meter: horizontal bar (e.g. x=20,y=210,w=120,h=10) filling GREEN(3)->YELLOW(10)->RED(8) as
  steep approaches STEEP_MAX; label "STEEP".
- HEAT bar: vertical or horizontal, color-coded (GREEN->YELLOW->RED).
- TIMER bar: horizontal top.
- SUPER: rainbow border (cycle border color each frame among the 4 tea colors), floating "SUPER BREW!".
- Particles: happy green/white on match, red on wrong, cyan on over-steep, gray on guest leave.
- Screen shake on mismatch and over-steep (shake_frames = 6).

## Animation / Timing Rules
- Color cycle: CYCLE_F starts 20, decreases to 12 by 60s: `cycle = 20 - (elapsed_frames // 450)`
  clamped to [12, 20]. Simpler: `20 - (elapsed // 450)` with min 12.
- Guest spawn interval: 90f -> 40f over 60s: `spawn = 90 - (elapsed // 60)` clamped [40, 90].
- Steep: +1/frame, STEEP_MAX=45, over-steep heat+12.
- SUPER duration 300f.
- PATIENCE_MAX = 600.

## Particle System
- On match: 8 particles, GREEN/WHITE, vel random (-1..1, -2..-0.5), life 20-30, no gravity.
- On SUPER match: 20 particles, all 4 tea colors, vel (-2..2, -3..-1), life 25-40.
- On wrong: 4 particles, RED, vel (-1..1, -1..1), life 15.
- On over-steep: 4 particles, CYAN, life 15.
- On guest leave: 4 particles, GRAY, life 15.

## Input
- Mouse click: map to seat if within seat hitbox -> self.serve(seat).
- Keys 1, 2, 3 -> self.serve(0/1/2).
- TITLE / GAME_OVER: KEY_RETURN or SPACE -> start / restart.

## Headless Testing Pattern
- Use `Game.__new__(Game)` to bypass __init__ (avoids pyxel.init/run panic).
- Pre-init ALL instance attributes (listed above) before calling reset().
- Never call pyxel.btn/btnp/mouse_x/mouse_y in testable methods.
- Separate logic from input: `serve(seat)` is the core; a click/keys wrapper maps input to it.
- Define `_make_game()` factory in test file: pre-init attrs -> g.reset() -> g.rng = random.Random(42).

## Edge Cases
- serve on empty seat -> return "empty", no state change.
- All seats full when spawning -> skip spawn.
- combo starts 0; first match makes combo=1, score += 10*1*mult (>= 10, never 0).
- heat check must fire BEFORE decay (decay-before-threshold bug).
- steep_mult uses integer division; steep never exceeds STEEP_MAX (reset at 45).
- guest patience decrements each _update_guests call; expired guest removed same call.
